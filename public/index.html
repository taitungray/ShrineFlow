如何建 App、拿 Token、換長期 ›
Meta 工具 建立應用程式 → Graph API Explorer → Token Debugger →

ShrineFlow 不會跳出 Facebook 登入。三個平台共用同一個 Meta App。不要把 App Secret 填在本頁。

建 Meta App（三平台共用）

  1. 到 Meta for Developers 建立應用程式，類型選 Business。
  2. 你的 Facebook 帳號必須是粉專管理員，並加進這個 App 的角色（管理員或開發者）。
  3. 使用案例要勾（精選常常沒有，改點「內容管理」或「全部」）：
    • 管理粉絲專頁的所有內容 → Facebook
    • 管理 Instagram 的訊息和內容 → IG
    • 存取 Threads API → Threads
    「使用 Facebook 登入」沒出現就往下走。不要勾廣告、WhatsApp、遊戲、oEmbed、Messenger。
  4. 商家沒有就跳過。自己粉專先維持開發模式，不必立刻 App Review。
  5. 儀表板：使用案例 → 自訂（Pages API）→ 權限。這頁才是加權限的地方。pages_show_list 若已「可供測試」就略過。對 pages_manage_posts、pages_read_engagement 按「+ 新增」。不要加 manage_pages／publish_pages。IG 再到 Instagram 使用案例加 instagram_basic、instagram_content_publish。

第一次：拿粉專 Token

  1. 開 Graph API Explorer，App 選這個應用程式。右側勾剛加的三個權限，按「產生存取權杖」。
  2. 右側 EAA... 是用戶權杖，不要貼進上面欄位。GET me?fields=id,name：name 應是人名。這份 JSON 不是 Token；id 不是粉專 ID。
  3. GET me/accounts?fields=id,name,access_token&limit=100。左邊 JSON 的 data[] 才是粉專清單。下拉常常沒粉專，不要靠它，也不要為此再產一次權杖。
  4. 對應 name 那筆：id → 粉專 ID；access_token → Page Access Token。貼上、儲存、測試。成功顯示粉專名稱＝已通。

之後：換成長期粉專 Token

只改網址成 me/accounts 不會變長期。不要在 Explorer 跑 oauth/access_token（常出現錯誤 101）。要先延長用戶權杖，再重查粉專 Token。

  1. 確認仍是用戶權杖（me?fields=id,name 是人名）。只複製右側 EAA...，不要複製 JSON 或 id。
  2. 開 Token Debugger → 除錯 → 按藍色 延伸存取權杖（英文介面寫 Extend Access Token）。沒有此按鈕＝貼成粉專 token 或 App 選錯。
  3. 延長後的用戶權杖貼回 Explorer 右側，再 GET me/accounts?fields=id,name,access_token&limit=100。用粉專那筆 access_token 覆寫上面欄位 → 儲存 → 測試。
  4. Debugger 看粉專 Token：Expires 為 Never 才算換成。到期日留白。改密碼、撤銷 App、失去粉專角色才會失效。

備援：也可用 App 編號＋密鑰做 grant_type=fb_exchange_token，但不要在 Graph Explorer 做。密鑰不要填進本頁。

常見踩雷

  • Cannot parse access token → 貼到的是 JSON 或數字 ID，不是 EAA...。
  • data 空陣列 → 登入帳號必須是粉專管理員，且跟 App 角色同一個 Facebook。
  • 短效 Token 約 1–2 小時；發文突然失敗就重拿粉專 Token 或走長期流程。

如何取得 Instagram 憑證 ›
  1. 同一個 Meta App。使用案例勾管理 Instagram 的訊息和內容。IG 必須是專業帳號，並綁這個品牌的 Facebook 粉專。
  2. App 儀表板該使用案例 → 權限：加 instagram_basic、instagram_content_publish。Explorer 搜尋不到＝還沒加進使用案例。
  3. 用已含 IG 權限的粉專 Token。GET me/accounts?fields=id,name,instagram_business_account，或 GET {粉專ID}?fields=instagram_business_account。
  4. instagram_business_account.id 貼 User ID。沒這欄＝還沒綁粉專或權限不足。Access Token 貼同一串 Page Token。到期日可留白。
目前品牌的 Threads

數字 User ID＋Threads Token。不要貼 Facebook 的 EAA...。

Threads 文件 →
如何取得 Threads 憑證 ›
  1. 同一個 Meta App。勾使用案例存取 Threads API，儀表板再加入 Threads 產品。
  2. 用 Threads 帳號授權取得 Token（開頭常是 THQVJ...）。不要把 FB 的 EAA... 貼來這裡。
  3. 對 Threads Graph（graph.threads.net）GET /me，數字 id 貼 User ID。那不是粉專 ID。
  4. 純文字可不設媒體網址；有圖／影則必須 HTTPS（如 https://media.shrineflow.uk）。到期日可留白。
備份與儲存管理
備份範圍與上限 ›

備份包含 JSON 內容、排程、品牌、平台快照與發布紀錄；不包含 `.env`、Token 或其他秘密。JSON 寫入採單檔鎖定、原子替換與單一復原快照；主要集合另有筆數／檔案大小硬上限，達上限時停止新增，不自動刪除內容。還原前會自動建立目前資料的安全備份。備份最多保留最近 30 份，且超過 180 天會自動清理；發布事件與 Insights 歷史最多保留 24 個月，單月檔案也有紀錄數上限。Inbox webhook 只保留最多 200 筆同步提示。
